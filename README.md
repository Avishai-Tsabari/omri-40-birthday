# חפש את המטמון — עומרי בן 40

אתר סטטי ליום ההולדת (27.08.2026). בלי שרת, בלי בנייה, בלי התקנות.

**המסלול:**

1. שולחים לעומרי את הלינק **בבוקר**.
2. הוא פותח → **ברכה מונפשת** (קונפטי, 40 בזהב).
3. אחרי כמה שניות → **ספירה לאחור ל-17:00** (שעון ישראל, לא משנה איפה הטלפון שלו).
4. ב-17:00 מופיע כפתור → **סרטון הפתיחה** נפתח ומגלה את התחנה הראשונה.
5. משם: קוד מהאחיין → סרטון נבל → התחנה הבאה. חמש פעמים.
6. **3 טעויות ברצף** → נפתח סרטון של אחיין עם ברכה ו"הקוד שגוי", ואז חוזרים לנסות.

אם הוא פותח את הלינק אחרי 17:00 — הברכה רצה ומיד אחריה נפתח כפתור הפתיחה.
אם הוא סוגר וחוזר באמצע המשחק — הוא ממשיך בדיוק מאיפה שהיה.

## הרצה מקומית

```bash
cd C:\code\agentic\omri-40-birthday
python serve.py
```

ואז `http://localhost:8080`.

שתי הערות:
- **לא** להשתמש ב-`python -m http.server`. הוא לא תומך ב-Range requests, ובלי זה
  הדפדפן מסרב לנגן וידאו — הסרטון נתקע על מסך שחור. `serve.py` פותר בדיוק את זה.
  אירוח אמיתי (Netlify / Vercel / Pages) תומך בזה מעצמו.
- פתיחה של `index.html` ישירות מהדיסק תעבוד חלקית — הסרטונים עלולים להיחסם.

## שינוי תוכן

**כל מה שמשנים נמצא ב-`config.js` בלבד.** אין צורך לגעת בקוד.

- טקסטים, שמות תחנות, שמות נבלים — שם.
- להוסיף או להוריד תחנה — להוסיף/למחוק אובייקט במערך `stops`. הכל מסתדר לבד.
- **מעבר משרונה לנמל או להפך** — לשנות את `next.place` ואת `next.text`. זהו.

### שעת ההתחלה

```js
countdown: { startsAt: '2026-08-27T17:00:00+03:00' }
```

ה-`03:00+` הוא מה שמבטיח שהספירה נכונה גם אם הטלפון של עומרי באזור זמן אחר.
אם השעה זזה — משנים כאן, וזה נקרא מחדש בכל שנייה.

### חשיפת המתנה

```js
revealGiftInApp: false
```

`false` = מסך הסיום רק שולח למסעדה.
`true` = מסך הסיום חושף את המדפסת. אפשר לשנות אפילו במהלך הערב (צריך רענון דף).

## רשתות ביטחון לערב עצמו

- **הסרטון לא נטען?** האתר מציג את התמלול של הנבל במקום. המשחק ממשיך.
- **הסרטון נתקע?** אחרי 3 שניות מופיע כפתור "דלג לרמז".
- **הדף נסגר או הטלפון מת?** ההתקדמות נשמרת. פתיחה מחדש חוזרת לאותו מקום.
- **תפריט מפעיל** — **לחיצה ארוכה (כשנייה) על הכותרת** פותחת רשימה של כל התחנות,
  ואפשר לקפוץ לכל אחת מהן. זה למקרה שמשהו משתבש בשטח. אל תדגים את זה לעומרי.
- **איפוס** — בתוך תפריט המפעיל. מחזיר גם את הברכה ואת הספירה.
- **חזרה להתחלה בזמן בדיקות** — להוסיף `?reset=1` לכתובת:
  `http://localhost:8080/?reset=1`. מנקה הכל ומתחיל מהברכה.
  הכתובת מתנקה מיד אחרי, כך שרענון באמצע המשחק לא יאפס בטעות.
- **עדכנת קובץ אחרי שכבר שלחת את הלינק?** צריך להעלות את `?v=` ב-`index.html`
  (שלוש שורות בתחתית הקובץ ואחת ב-head). בלי זה הדפדפן של עומרי ימשיך להריץ
  את הגרסה הישנה מהמטמון. זו לא תיאוריה — זה קרה כאן בפיתוח.

## כתובות (routes) ומשמרות

לכל מסך יש כתובת, כדי שבבדיקות אפשר יהיה לקפוץ ישר לאן שצריך ושכפתור
"אחורה" יתנהג כמו "המסך הקודם" ולא כמו "צא מהאתר".

| כתובת | מה זה |
|---|---|
| `#/greeting` | הברכה |
| `#/countdown` | הספירה לאחור |
| `#/code` | הזנת קוד |
| `#/stop/N` | הסרטון של תחנה N (מתחיל מ-1) |
| `#/next/N` | הרמז לתחנה הבאה |
| `#/wrong` | סרטון "הקוד שגוי" |
| `#/finale` | מסך הסיום |

**כתובת עירומה** (בלי `#`) תמיד נכנסת דרך `#/greeting`. זו נקודת הכניסה,
וזה מה שעומרי יקבל כשילחץ על הלינק ששלחת לו.

**המקום נשמר.** הכתובת האחרונה נשמרת ב-`localStorage` יחד עם ההתקדמות:

- **רענון עם `#` בכתובת** — נשאר בדיוק באותו מסך, בלי לעבור דרך הברכה.
- **פתיחה של הלינק העירום באמצע המשחק** — הברכה רצה, ואז הוא חוזר *למסך
  המדויק* שהיה בו, לא להתחלה של המשחק.
- אם הכתובת השמורה כבר לא מותרת (למשל אופסה ההתקדמות) — נפילה רכה למסך
  הנכון, בלי שגיאה.

`#/greeting` ו-`#/wrong` לא נשמרים: הראשון הוא נקודת כניסה, השני רגע חולף
שאין טעם לשחזר.

**המשמר:** אף כתובת לא יכולה לקחת את עומרי קדימה. מקור האמת נשאר
`state.unlocked` ב-`localStorage`; הכתובת רק *מבקשת*, והמשמר מאשר או מחזיר
אותו למסך שהוא באמת אמור להיות בו. אם הוא יקליד `#/stop/6` באמצע המשחק —
הוא ינחת ב-`#/code`. `#/finale` נפתח רק אחרי שהתחנה האחרונה נוגנה.
כתובת שלא קיימת מתנהגת אותו דבר.

ההפניה נעשית ב-`replaceState`, כך שקפיצה חסומה לא משאירה רשומה מתה
בהיסטוריה — "אחורה" ממשיך לעבוד כרגיל אחריה.

זה נבדק: מהברכה כל קפיצה קדימה חוזרת לברכה; אחרי פתיחת התחנה הראשונה
`#/stop/1` מותר ו-`#/stop/2`, `#/stop/6` ו-`#/finale` חסומים; ואחרי סיום
המשחק שניהם נפתחים.
